## 11a. Technical Build Specification (for Claude Code)

**Framework & stack (DECIDED):**
- **Next.js** (App Router) with **TypeScript**
- **Tailwind CSS** for styling
- **shadcn/ui** for components
- **next-intl** for i18n (English / Bangla), locale-prefixed routes (`/en`, `/bn`)
- Icons: lucide-react
- Fonts: a clean sans for English + a Bangla-capable font (e.g. Noto Sans Bengali) for Bangla — set up both in the font config.

**Hosting / deployment (DECIDED):**
- **Vercel.** Structure the project so it deploys to Vercel with zero config.
- Target domain: **starshipintlbd.com** `[CONFIRM this is the live domain]`

**Forms (DECIDED — email only, no database):**
- Use **Web3Forms** (recommended: free, no backend, works on static/Vercel; just needs a public access key) OR a Next.js Route Handler using **Resend**. Default to Web3Forms unless the client prefers Resend.
- Both the **Contact form** and **Quote form** submit via this service and email the submission to the company inbox.
- Recipient inbox: `[CONFIRM — e.g. starshipdhaka@gmail.com]`
- Include client-side validation, a success state, an error state, and basic spam protection (honeypot field).
- **Secrets:** any API key goes in `.env.local` and Vercel env vars — never hardcoded, never committed. Provide a `.env.example`.

**i18n handling:**
- All user-facing copy lives in translation files (`messages/en.json`, `messages/bn.json`).
- Fill `en.json` with real English copy. Fill `bn.json` with placeholder values marked `BN_TODO` so the client can replace them.
- Language switcher visible in the header on all pages.

**Project structure:** standard Next.js App Router layout, one route per page (Section 4), shared layout with header/footer, components in a `components/` folder.

**Quality bar:**
- Mobile-first responsive.
- Semantic, accessible HTML (WCAG-minded: alt text, color contrast, keyboard nav, focus states).
- SEO: per-page `metadata` (title + description), Open Graph tags, `sitemap.xml`, `robots.txt`, and local-SEO keywords for C&F/customs in Chittagong, Benapole, Dhaka.
- Optimized images via `next/image`.
- No secrets in the repo; clean `.gitignore`; ready for GitHub.

**Images / assets:**
- Real logo and photos to be provided by the client. Until then, use clearly-labeled **placeholders** (e.g. a placeholder logo and stock-style blocks) — do NOT fabricate a logo. Mark every placeholder in code with a `TODO` comment.
